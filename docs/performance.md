# 0.5 性能复测

日期：2026-09-08。复测入口：`scripts/performance.ps1`。原始结果：`artifacts/performance/results.json`。

## 方法与范围

Release / .NET Framework 4.8 / Windows，本机文件系统，测试程序直接编译生产版本的 TargetNode、FileNode 并引用生产 Core，在 WPF Dispatcher 上调用加载与刷新方法。
分别创建 10,000 和 100,000 个真实空文件，放在单个目录中；模型包含一个大型目标和一个共享文件目标。表格来自文件已存在时的一次运行，不是多轮统计或冷磁盘结果。
归属查询基线保留 0.3 的逐目标逐源码 Paths.Equal 扫描方式，查找最后一个文件。计时不包含基线在 Dispatcher 间隔指标中。

| 指标 | 10,000 文件 | 100,000 文件 |
|---|---:|---:|
| 后台建立归属索引 | 10.16ms | 99.50ms |
| 构造折叠目标根节点（含任务调度） | 2.17ms | 0.26ms |
| 展开目标及其源码目录，生成分页节点 | 112.46ms | 1,391.80ms |
| 新索引查询 10,000 次 | 6.38ms | 7.00ms |
| 旧扫描逻辑查询 100 次 | 1,169.37ms | 12,654.55ms |
| 首次读取真实目录 | 56.82ms | 1,208.92ms |
| 无变更目录刷新 | 54.96ms | 1,176.30ms |
| Dispatcher 最大采样间隔（10ms 计时器） | 30.72ms | 30.62ms |
| 测试阶段托管堆差值，约 | 6.3MiB | 61.3MiB |

折叠节点只有两个目标，因此根节点构造时间不代表千目标工程；极小时间主要受预热与调度影响。展开和目录读取的总耗时主要在后台，不等于 UI 冻结时间。堆差值包含索引、展开后的数据节点和文件节点，不是 VS 总内存，也不是峰值。

## 行为检查

- 大小写路径归属、跨目标共享、单目标重复引用去重、缺失文件归属。
- 取消的索引构建停止；折叠树不创建全部文件节点。
- 同一节点并发展开不重复加载；每页最多 500 文件，内容正确。
- 真实目录完整读取；无变化刷新保持原集合。
- 不相关目录事件不枚举；相关目录变更刷新后复用未改变节点。
- 十万次并发事件合并为同一个目录；十万个不同目录触发有界溢出回退；重命名保留新旧父目录，内容变化不请求目录枚举。这些直接测试生产事件批处理器，不是十万个真实 FileSystemWatcher 通知的端到端测试。
- 97 项功能/集成检查通过，包含 File API 多配置读取、新建及批量引用、完整工程创建、移动恢复、真实 MSVC 构建和 CTest。

## 边界

这证明关键数据路径已改善，不保证任意大工程在 VS 内都不卡。这里没有加载完整 VS 外壳或测量真实 TreeView 渲染，也未计入 VA、IntelliSense、CMake 配置与编译时间。
十万文件的 File API JSON 读取、千目标多配置切换、持续构建事件风暴和网络磁盘尚无端到端基准。旧配置的索引与读取会取消，已开始的单个 JSON 解析不能立即中止。
真实目录仍一次持有该目录全部 FileNode；目标文件节点分段加载。批量移除对话框和超大脚本完整预览尚未专门分页。
后续应在用户实际工程中测量完整 VS 的打开、切换配置和交互延迟，再决定是否引入进一步缓存。
