# 实施记录与后续任务

## 0.1：基础闭环

已实现工具窗口、目录树、File API 查询与读取、目标配置切换、文件归属、新建源码预览与写入。
构建使用传统 VSSDK，公共库独立于 VS；当前把 UI 和平台适配合在一个 VSIX 项目，随复杂度增长再拆分。

## 0.3：目标管理

已实现目标树与实际源码目录分组、生成/外部标签、批量加入已有文件、批量移除引用、新建程序/静态库/动态库及父目录连接。
修改统一通过 VS 文本缓冲区预览与应用，保留未保存编辑并进入撤销历史。新建实体文件不会随脚本撤销删除。
对条件、变量、函数、FILE_SET 等无法可靠处理的引用保持只读；本阶段不实现 VA 联动或代码补全、符号导航和代码重构。

## 0.4：大工程性能

已实现后台文件归属索引、目标与目录按需展开、宽目录每 500 文件分段、目标树虚拟化、后台配置输入检查、过时读取取消及结果隔离。
移除目录刷新中的逐项 IndexOf，未变化时保留集合，有变化时复用节点并一次替换集合；节点记录展开与选择状态。
文件事件不再逐条投递 UI，固定周期合并并按目录刷新，队列最多保留 2048 个目录，超过上限回退到已加载目录全刷新。
一万/十万真实文件的 .NET Framework 4.8 Dispatcher 基准与行为检查见 performance.md；未将独立基准当作完整 VS 大项目验收。

## 0.5：三个阶段的工程与文件工作流

1. 已实现完整工程创建与打开、文件/路径搜索、目录显示规则及展开状态保存。
2. 已实现新建目录、文件与纯源码目录移动/改名、跨脚本字面量引用预览与持久操作日志恢复。
3. 已实现文件树内部拖放、共用的菜单操作流程、空工作区入口和模型状态提示。

使用步骤、保护边界与实测范围见 [0.5 工作流](workflows-050.md)。复杂 CMake 引用继续保守拒绝，不把文件路径变更当作 C++ 代码重构。

### 0.2 接口依据

- [IVsFolderWorkspaceService](https://learn.microsoft.com/en-us/dotnet/api/microsoft.visualstudio.workspace.vsintegration.contracts.ivsfolderworkspaceservice?view=visualstudiosdk-2022)：打开文件夹的当前工作区和切换事件。
- [IWorkspace](https://learn.microsoft.com/en-us/dotnet/api/microsoft.visualstudio.workspace.iworkspace?view=visualstudiosdk-2022)：根路径、配置服务和属性求值服务。
- [VS Preset 属性替换](https://learn.microsoft.com/en-us/cpp/build/cmake-presets-vs?view=msvc-170#variable-substitution-in-launchvsjson-and-tasksvsjson)：当前配置属性的 `${cmake.<KEY-NAME>}` 求值。插件实际验证了 `name`、`binaryDir`；兼容旧配置的 `buildRoot` 尚无完整场景验证。

没有引入私有 CMake DLL，也不读取 `.vs` 内部状态文件来猜测当前 Preset。

## 验收原则

每个支持的文件变更场景，都必须同时检查磁盘、脚本、CMake 模型和实际构建结果。
界面可打开、SDK 构建成功、VSIX 可部署、断点可命中是不同的验证项，分别记录，不相互替代。
