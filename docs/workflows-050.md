# 0.5 工程与文件工作流

## 创建和浏览

从“工具 → 创建 CMake 工程…”或插件工具栏创建按钮进入向导。填写工程名、已有父目录，选择程序/静态库/动态库、C++17/20/23，以及是否生成 CTest 示例。检查文件预览后创建；只接受全新目录，不覆盖已有工程。

模板生成 CMakeLists.txt、src、include、.gitignore 和 Debug/Release Ninja Presets；测试选项生成可运行的 smoke 测试。创建完成后使用 VS 的打开文件夹服务打开工程，配置、编译与调试使用 VS 原生入口。工具栏也支持选择已有 CMake 工程。

搜索框匹配文件名或相对路径，后台执行，可取消，最多显示 500 项；清空返回目录树。齿轮中可设置分号分隔的目录排除规则（支持 *、?），也可显示排除目录。规则和最多 200 个展开目录按工程保存到本机用户设置中。

## 移动、改名和恢复

文件树右键菜单和“+”菜单提供新建目录、重命名、移动到、恢复最近文件操作。内部拖放把文件或纯源码目录拖到目标目录，进入同一移动预览流程；不支持外部拖放。

执行前需要一个未过期的 CMake 模型，且相关编辑器文档已保存。预览包含旧路径、新路径及所有受影响脚本的修改前后内容。确认后关闭相关已保存文档，移动实体路径、写入脚本，并等待 VS 重新配置后读取新模型。

移动/改名使用“恢复最近文件操作…”，不使用编辑器 Ctrl+Z。日志保存在 `%LOCALAPPDATA%\CMakePlus\operations`，先写日志再移动。恢复校验文件内容与脚本状态，支持文件已移动、部分脚本已写入等中断状态；如果文件后来被编辑或目标路径发生冲突，停止恢复并保留现场。

新建源码、新建目标、加入/移除目标引用仍使用原有 VS 文本缓冲区编辑与 Ctrl+Z；恢复日志不覆盖这些功能，也不覆盖完整工程创建。

## 支持边界

- 自动更新直接、无条件的字面量源码引用；涉及条件、变量、FILE_SET 或无法定位的引用时拒绝移动。
- 不移动 CMakeLists.txt、.cmake 脚本或包含这类文件及 Presets 的目录，不处理仅大小写变化的改名。
- 不更新 C/C++ 的 #include、运行时路径或其他字符串。目录移动不会自动完成代码重构。
- 仅本机工作区内部操作；拒绝覆盖、越界、目录链接及生成文件。
- 文件与多个脚本之间不是断电原子事务；持久日志用于检查并恢复可识别的中断状态。
- 模型提示区分等待配置、等待重新配置、索引加载和已读取快照；已读取模型不代表编译成功。
