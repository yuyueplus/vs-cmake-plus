# 0.5.1：新建源码预览无响应

用户截图中的状态栏提示“自动修改要求 UTF-8 无 BOM，请先转换脚本编码”。原有编辑器适配及源码规划器均拒绝带 BOM 的 UTF-8 文件；失败仅写入工具窗口底部，缺少对话框内反馈。

修复：

- 编辑器适配和源码规划器统一使用严格 UTF-8 解码，接受开头的 UTF-8 BOM，正文不包含编码前缀。
- 仍使用当前 VS 文本缓冲区生成补丁，保留未保存编辑；保存时统一使用 UTF-8 无 BOM，预览说明该行为。
- 新建源码对话框先验证并生成计划，成功才关闭并进入预览；失败直接显示原因，保留输入以便修正。
- 其他非 UTF-8 编码继续明确拒绝，不猜测转码。移动/恢复流程的无 BOM 限制本次未改变。

验证：103 项核心及真实 CMake/MSVC/CTest 集成检查通过，新增 6 项覆盖 BOM、中文、CRLF、未保存正文、应用后的无 BOM 输出，以及 UTF-16/无效 UTF-8 拒绝。VS 2022 与 VS 2026 SDK 构建通过。此次未在用户日常 VS 实例中安装或执行文件操作。

安装包：artifacts/release/CMakePlus-0.5.1.vsix。关闭 VS 后安装更新，重启再使用“新建源码 → 预览修改 → 应用修改”；保存 CMakeLists.txt 后重新配置。
