# CMake Plus

面向 Visual Studio 2022 / 2026 的 CMake 项目管理增强插件，当前为 **0.8.3 实验版**。

0.8.3 将配置命令改为在 VS 2022 Keyboard 命令列表核实的 `Project.ConfigureCache`。新建与文件操作统一请求配置；增加 Retry VS Configuration，保留命令失败提示，新建菜单不再因等待状态变灰（提交仍检查最新模型）。已在当前 VS 工程通过原生 Project > Configure 验证 Loaded 状态恢复；新版自动调用尚未在主机部署验证。

0.8.2 修复删除前模型刷新被文件操作锁跳过的问题，并在等待配置期间定时重查模型。新增真实 CMake 新建同名目标后再次删除回归检查。VS 界面的等待状态解除仍需实际验证。

0.8.1 在删除、移动和恢复后请求当前 VS 工作区 Generate Cache，并等待新模型；命令不可用时提示手动生成。修复删除后继续新建被旧模型拦住的刷新流程。主机命令交互仍需实际 VS 验证。

0.8.0 支持独立目标目录删除：选中目录或目标，使用 Delete to Recycle Bin，预览并移除父脚本入口及直接链接/构建依赖，再回收目标目录。支持范围见 [目标删除](docs/target-deletion-080.md)。

0.7.0 将新建源码、目标和引用编辑的 Apply Changes 接入脚本保存及配置等待流程：只保存本次修改的脚本，原有未保存编辑先确认；等待新成功模型期间暂停相关目标编辑。右键新建源码使用所选目录的路径，优先选择实际文件归属或最近声明目录的唯一目标。若关闭了 VS 自动配置，仍需从 VS 手动重新配置。详细说明见 [连续创建工作流](docs/workflow-070.md)。

0.6.4 修复 VS 默认模板包含 if(POLICY CMP0141) 时无法新建目标的问题。完整闭合的条件块可以保留，新的 add_subdirectory 追加在所有块外；仍拒绝块结构不完整、return() 或无法解析的子目录引用。

0.6.3 将 New Source File / New Target 的模型检查移到对话框内的 Preview Changes 阶段。模型缺失或过期时仍可打开输入窗口，预览时显示具体错误并保留输入；应用前仍检查模型与脚本冲突。操作外层异常显示弹窗，避免仅更新底部状态。

0.6.2 修复右击嵌套文件时选中节点跳到工程根节点的问题，文件树与目标树统一使用最近的树节点处理右键选择。

0.6.1 将扩展自身的操作界面统一为英文，包括菜单、按钮、提示、预览、错误信息及撤销操作名称。下文中文操作名对应功能不变，英文入口见 [English UI guide](docs/english-ui.md)。系统对话框及 VS 自身消息仍使用宿主语言。

0.6.0 新增右键及“+ → 删除到回收站…”：预览删除文件/目录及 CMake 引用，执行前检查冲突与未保存文档。使用及恢复步骤见 [删除功能](docs/deletion-060.md)。

0.5.1 修复 VS 模板带 UTF-8 BOM 时无法预览新源码的问题；输入或编码错误直接显示在新建源码对话框内，保留输入供修改。编辑器脚本操作接受 UTF-8 BOM，应用后保存为 UTF-8 无 BOM；移动/恢复的磁盘流程仍要求无 BOM。

## 已实现

- 创建完整 CMake 工程：程序、静态库、动态库，选择 C++17/20/23，可生成 CTest 示例；预览后创建并由 VS 打开文件夹。
- 后台文件名/路径搜索、可配置目录排除规则、显示排除目录、按工程保存规则与目录展开状态。
- 新建目录、源码文件及纯源码目录改名/移动，预览并同步受支持的 CMake 字面量引用。
- 文件树内部拖动到目录，使用同一套移动预览、冲突检查及持久日志恢复流程。
- 空工作区创建/打开入口与独立模型状态提示。详细使用与验证范围见 [0.5 工作流](docs/workflows-050.md)。
- 可停靠的工具窗口，从 **工具 → CMake Plus** 打开。
- 紧凑图标工具栏、文件/目标视图下拉切换、默认收起的工作区设置；新建和引用操作位于“+”菜单及树的右键菜单。
- 控件使用 VS 主题样式，文件树使用 VS 图标和整行选中效果；状态摘要悬停显示完整内容。
- 自动跟随 VS 打开的 CMake 文件夹，读取 VS 已展开的当前配置/Preset、构建目录和构建配置；保留手动选择模式。
- 工作区与配置切换时清空旧模型，构建目录就绪后准备查询，新 File API 回复到达后自动加载。
- 真实目录树、懒加载、外部修改合并刷新、双击打开源码、定位活动文档。
- 创建独立的 CMake File API 查询，读取最后成功配置的目标和多配置数据。
- 查看文件所属目标，双击目标打开声明文件。
- 文件归属索引在后台建立；目标树按需展开，超过 500 个文件的目录分段显示，启用目标树虚拟化。
- 文件事件每 600ms 合并处理，结构变化只刷新受影响的已加载目录，内容保存不重建目录树；超量事件回退到已加载目录刷新。
- 目标树按实际源码目录分组，标记生成文件和外部文件；同一文件可以属于多个目标。
- 批量加入已有文件、批量移除目标引用；移除引用保留磁盘文件。
- 新建程序、静态库或动态库，生成目录、基础源码及子目录脚本，并连接父 `add_subdirectory`。
- 新建 C/C++ 源码及头文件，预览并在明确目标声明后插入 `target_sources`。
- 预览包含编辑器未保存内容；修改进入 VS 文本缓冲区及撤销历史，应用时检查脚本和磁盘并发变化。

## 环境

- Windows x64。
- VS 2022 **17.14+** 或 VS 2026，安装 C++ 桌面开发和 CMake 工具。
- 编译插件需要 .NET SDK 8.0.203 或同一主版本的较新功能带，以及 .NET Framework 4.8 开发工具。
- 当前使用的 VSSDK 依赖基线是 17.14；尚未向较早的 VS 2022 小版本回移。
- 集成测试使用 CMake 3.20+ 与 Visual Studio 17 2022 生成器。本机使用 CMake 3.29.3。

## 构建与测试

在项目根目录运行：

```powershell
.\scripts\build.ps1 -VisualStudio 2022
.\scripts\build.ps1 -VisualStudio 2026
.\scripts\test.ps1 -Integration
```

安装包输出到 `artifacts/release/CMakePlus-0.8.3.vsix`。
运行 `.\scripts\performance.ps1` 可复测一万和十万真实文件，结果与适用范围见 [性能验证](docs/performance.md)。测试会在 `artifacts/performance` 创建共 110,000 个空文件。
集成测试会在 `artifacts/tests/` 创建独立样例，不修改 `samples/hello`。

开发时建议部署到独立实验配置：

```powershell
.\scripts\build.ps1 -VisualStudio 2022 -DeployExperimental
```

关闭对应实验实例后再更新插件。以 Visual Studio 的 `devenv.exe /RootSuffix CMakePlus` 启动；首次启动可能出现账户和个性化设置。
部署脚本只面向 `CMakePlus` 后缀，不向日常实例部署。

## 体验步骤

1. 在 VS 中以文件夹方式打开 `samples/hello`，等待 CMake 配置完成。
2. 从 **工具 → CMake Plus** 打开插件。
3. 默认勾选 **跟随 VS 工作区**，等待自动显示路径与 `windows-vs2022` 配置/Preset。已有 File API 模型会自动读取。
4. 首次使用若提示等待回复，在 VS 中重新配置一次 CMake；插件自动读取新回复。选择目录会进入手动模式，可再次勾选恢复跟随。
5. 在视图下拉框选择 **目标** 查看 `hello`；旁边的配置下拉框只切换插件查看的模型，不切换 VS 配置。工具栏齿轮打开目录及查询设置。
6. 从工具栏 **+ → 新建源码…** 输入 `extra.cpp`，选择 `hello`，查看补丁后应用。
7. 保存被修改的 CMake 脚本，使用 VS 原生入口重新配置和构建，自动模式会读取新模型，确认 `extra.cpp` 已属于 `hello`。
8. 在目标树选中目标或它的文件，从右键菜单或 **+** 菜单使用 **加入现有文件…** 或 **移除目标引用…**。应用前可查看完整修改前后内容。
9. 从 **+ → 新建目标…** 填写名称、类型、新目录及父脚本。应用后保存父脚本并重新配置，新目标即出现在目标树。
10. 新建源码/目标及引用编辑后，在脚本编辑器中按 Ctrl+Z 撤销。新建实体文件保留；下一次目标操作前先保存和重新配置。移动/改名使用单独的“恢复最近文件操作…”，不使用 Ctrl+Z。

样例预设明确使用 VS 2022 的工具链；只有 VS 2026 的机器应自行选择匹配工具链的 Preset。插件宿主版本与工程编译器版本是独立的。

## 当前边界

- 配置、构建和调试仍使用 VS 原生入口。上下文读取使用公开 Open Folder/属性求值服务，不使用私有 CMake 程序集，不自行实现 Preset 继承和宏展开。
- 自动跟随仅支持本机 Windows 绝对构建路径。服务未就绪、未确定源码根目录、远程构建时显示原因并保留手动模式；没有接管 VS 原生 Solution Explorer。
- VS 原生构建事件和 File API 模型状态是不同信息。未收到事件时显示未知，不把有缓存或有目标误判为构建成功。
- 上下文事件配合可见窗口每 3 秒刷新；窗口关闭后停止计时。首次查询准备发生在构建目录创建之后，可能需要再次使用 VS 原生配置入口。
- File API 显示最后成功配置的快照。失败配置不能被当成一个新的成功模型。
- 新建源码只支持当前源码目录内、已有父目录下的文件；目标必须在 `CMakeLists.txt` 中以无条件字面量直接声明。
- 条件、函数、宏、变量、导入、别名、接口目标及 FILE_SET 等复杂引用保持只读。移除仅支持目标声明脚本内的直接字面量引用；生成及外部文件只读，不能移除全部源码。
- 新目标使用全新目录，父目录必须存在；允许完整闭合的控制流块，在块外追加子目录。父脚本存在 return()、不完整块结构或无法解析的子目录引用时停止自动连接。
- 编辑器脚本操作接受带或不带 BOM 的 UTF-8，应用后保存为 UTF-8 无 BOM；移动/恢复要求 UTF-8 无 BOM。新生成文件使用 UTF-8 无 BOM；保留原脚本换行和注释。
- 新建源码/目标及引用编辑进入 VS 撤销历史，应用后保存本次修改的脚本。原有未保存内容须确认一并保存，不会保存其他文档。保存失败会提示手动处理。
- 移动/改名/删除要求相关文档已保存；关闭相关已保存文档后同步写入磁盘与脚本。恢复前校验内容，拒绝覆盖后续编辑。删除恢复需先从 Windows 回收站还原文件，再恢复脚本。日志不是所有功能的通用撤销或断电原子事务。
- 不移动 CMake 脚本及包含脚本/Presets 的目录。删除仅对受支持的独立目标目录放宽此限制，参见目标删除说明。不支持仅改变大小写的改名；不修改 C++ `#include`、运行时路径或复杂变量引用。
- 新文件不覆盖已有文件；新工程仅写入全新目录。新建源码/目标的跨文件创建失败时保留已创建文件供检查。
- 默认隐藏 `.git`、`.vs`、`.cmake`、`out`、`build` 和 `cmake-build-*`，可在齿轮设置中调整；始终跳过目录链接。搜索最多显示 500 项，保存最多 200 个展开目录。
- 拖放仅支持本窗口文件树内部移入目录。Presets 编辑器、CTest 面板和远程开发待后续迭代。不包含代码补全、符号导航、代码重构或 VA 联动。

## 开发入口

- `src/CMakePlus.Core/CMakeModel.cs`：File API、目标与路径模型。
- `src/CMakePlus.Core/SourceEdit.cs`：CMake 词法扫描、补丁计划与执行。
- `src/CMakePlus.Core/TargetEditing.cs`：批量引用修改与新目标计划。
- `src/CMakePlus.Core/ProjectCreation.cs`：完整工程模板与创建。
- `src/CMakePlus.Core/FileOperations.cs`：路径变更、脚本补丁与持久恢复。
- `src/CMakePlus.Core/WorkspaceBrowser.cs`：搜索与工作区显示设置。
- `src/CMakePlus.Vsix/WorkspaceFeatures.cs`：创建入口、搜索、拖放、移动和恢复 UI。
- `src/CMakePlus.Vsix/VsScriptEdit.cs`：文本缓冲区、并发检查和撤销事务。
- `src/CMakePlus.Vsix/ExplorerControl.cs`：工具窗口、目录树、文件操作。
- `src/CMakePlus.Vsix/VsWorkspaceContext.cs`：公开 Workspace、配置和属性求值服务适配。
- `src/CMakePlus.Vsix/VsBuildMonitor.cs`：VS 原生构建事件适配。
- `tests/CMakePlus.Tests/Program.cs`：语法边界、冲突保护和真实配置构建测试。
- `docs/roadmap.md`：后续任务与验收标准。
